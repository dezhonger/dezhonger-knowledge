# 如何使用本站

Dezhonger 知识库按照你希望理解的系统边界组织，不要求从第一篇依次读到最后一篇。

## 选择阅读路径

| 你正在思考的问题 | 建议入口 |
| --- | --- |
| API 或服务应该如何组织？ | [后端工程](/zh/backend/) |
| 一次请求究竟在哪个阶段失败？ | [计算机系统](/zh/systems/) |
| 检索或排序效果为什么不理想？ | [AI 工程](/zh/ai/) |

每个部分都有一篇概览，用于定义边界；各篇文章集中回答一个问题。当不同层之间存在依赖时，文章会通过链接建立关联。

## 文章结构

大部分文章使用相同结构：

1. **问题**：文章希望回答的实际问题。
2. **模型**：足够准确且尽量简洁的心智模型。
3. **机制**：运行时真正发生了什么。
4. **失败方式**：模型在生产环境中容易失效的位置。
5. **检查清单**：得出结论前应该收集的证据。

目标不是记住更多术语，而是让下一次诊断或设计决策更准确。

## 语言

网站默认显示英文，可通过顶部导航切换为简体中文。两种语言拥有相同的信息结构，但分别维护 Markdown 源文件，使技术表达在两种语言中都保持自然。
